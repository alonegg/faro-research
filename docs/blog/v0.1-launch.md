# 我做了一个 A 股研究 Agent，开源给你

> 用过 dexter / autogen 的朋友会发现一个有意思的现象：
> 几乎所有"金融研究 Agent"默认都是给美股的。
> 中国市场的 LLM 工具链长期是空白。
> 周末写了两天，开源了一个填这个坑的小项目，叫 **Faro Research**。

---

## 起因：一个我自己用的小痛点

我自己有个 FOF（基金中的基金）配置系统，跟踪十来只 QDII / 港股通 ETF
的真实暴露。日常做研究的时候要不停问几个问题：

- 「贵州茅台现在 PE_TTM 多少？」
- 「宁德时代过去 6 个月有没有董监高减持？」
- 「比亚迪 2024 vs 2025 营收和归母净利对比给我」

理论上这些数据 Tushare 都有。但每次都要：

1. 想一下 ts_code 后缀（茅台是 `.SH` 还是 `.SZ`？）
2. 打开 IDE，写一段 `pro.daily_basic(...)`
3. 把 DataFrame 复制到飞书表格手动算
4. 隔半小时换个标的再来一遍

明明是机械动作，但 30 秒成本 × 每天 20 次 = 10 分钟，
还很容易因为重复工作产生「算了不查了凭印象判断」的傻逼决定。

刚好看到 [virattt/dexter](https://github.com/virattt/dexter)
这个英文金融 Agent，就想：能不能给中国市场弄一个？
顺手把它从 `claude.ai/code` 之类的对话窗口里独立出来，做成一个能 `docker compose up`
的小产品。

## 选型：为什么不直接 fork dexter

我读了 dexter 的代码，2000 多行 TypeScript。架构其实漂亮——
agent loop、provider 抽象、tool 注册表分得很清楚。
但数据层硬绑死在 `https://api.financialdatasets.ai`（美股 SaaS），
而且工具的 prompt 大量假设 SEC 10-K/10-Q/8-K 的 Item 编号体系。

A 股完全没有这个东西。年报章节是中文自由格式，巨潮上挂个 PDF。
要把 dexter 改成 A 股版，至少 60% 工具要改 endpoint + 字段，
30% 要重写语义（行业映射 GICS → 申万、复权 / 停牌 / ST 标记），
还有 10% 真做不出（一致预期数据 Tushare 不开源）。

**改不如重写。** 借设计模式不抄代码——
这是我个人用了几年的判断标准，对于这种规模的项目特别成立。

## 三个核心抽象

借鉴 dexter 的设计后，我把 v0.1 收敛到三个抽象：

```
Provider     ← 哪个 LLM
ToolSpec     ← 每个工具的 JSON 描述 + Python 函数
SessionStore ← 多会话历史 + 审计日志
```

工具的 ToolSpec 长这样：

```python
ToolSpec(
    name="get_key_ratios",
    description="Latest valuation snapshot (PE / PB / market cap, 4 quarterly ROE).",
    parameters={
        "type": "object",
        "properties": {"ts_code": {"type": "string"}},
        "required": ["ts_code"],
    },
    fn=lambda ts_code: {
        "valuation_snapshot": ts.daily_basic_latest(ts_code),
        "financial_indicators_quarterly": ts.fina_indicator_latest(ts_code, limit=4),
    },
)
```

注册到 `ToolRegistry`，agent 自己看 description 决定什么时候调。

Provider 抽象解决「绑定单一 LLM」的痛——v0.1 内置两个：

- `OpenAICompatibleProvider`：覆盖 OpenAI / DeepSeek / Moonshot Kimi /
  火山方舟 / Together / Groq / **Ollama 本地**
- `AnthropicProvider`：Claude 原生 Messages API

切换只要改一个 env 变量。我自己默认用 DeepSeek 推理模型，
单次成本几分钱人民币。

## 5 个内建 Tushare 工具

刚够覆盖日常 80% 的研究问题：

| 工具 | 数据 |
|---|---|
| `resolve_ticker` | 中文公司名 / 6 位代码 → ts_code（带歧义检测） |
| `get_stock_quote` | 最近 N 日 OHLCV |
| `get_key_ratios` | PE / PB / 市值 + 季度 ROE / 毛利率 / 同比 |
| `get_three_statements` | 利润表 + 资产负债表 + 现金流量表 |
| `get_holder_trades` | 董监高及关联人增减持 |

数据走 Tushare HTTP API（不是 SDK），少装一个 optional dep。

## 演示

完整安装到提问 < 30 秒：

```bash
git clone https://github.com/alonegg/faro-research.git
cd faro-research && cp .env.example .env
# 填 FARO_OPENAI_API_KEY 和 TUSHARE_TOKEN
docker compose up --build
# 浏览器打开 http://localhost:5173
```

或者纯 CLI：

```bash
pip install -e .
faro-research "贵州茅台 PE_TTM"
# → ## 贵州茅台（600519.SH）PE_TTM
# → | 指标 | 数值 |
# → |------|------|
# → | **PE_TTM** | **20.97** |
# → ...
# → 数据日期：2026-04-30
```

或者作为 Python 库嵌入你自己的工程：

```python
from faro_research import Agent, Message, ToolRegistry, make_provider
from faro_research.tools.builtin.tushare import tushare_tools

reg = ToolRegistry()
reg.register_many(tushare_tools())
print(Agent(make_provider(), reg).run([
    Message(role="user", content="比亚迪 2024 vs 2025 营收")
]).final_answer)
```

Web UI 是写在 React + Vite 里的轻量聊天页：左边会话列表，
右边对话；每次提问会有实时的 tool trace 折叠面板，你能看到 agent
"先调了 resolve_ticker、然后并行调了 key_ratios 和 holder_trades、
最后写了 markdown 输出"。每次问答自动持久化到 SQLite，关浏览器再开还在。

## 真正的杀手锏：插件协议

5 个内建工具只是开胃菜。真正能让你愿意把它接进自己工作流的，
是「30 行写一个工具」这件事：

```python
def my_portfolio(ticker: str | None = None) -> dict:
    # 这里去你自家的数据库 / Excel / Google Sheets / Wind 取数
    return {"ticker": ticker, "weight": 0.18, "as_of": "2026-04-30"}

PORTFOLIO_TOOL = ToolSpec(
    name="get_my_portfolio",
    description="读取用户当前持仓。可选传 ticker 过滤。",
    parameters={"type": "object", "properties": {"ticker": {"type": "string"}}},
    fn=my_portfolio,
)

reg.register(PORTFOLIO_TOOL)
```

`examples/custom_plugin.py` 里有完整可跑的版本。

如果你跑了我前面的 FOF 系统，可以把 `portfolio_context` /
`simulate_solver`（"如果把 NVDA 目标改成 25%，反求会怎么变"）
包成插件挂上去，agent 立刻就能跨域回答
"我现在 NVDA 合成暴露多少、跟目标差多少、补回去要换什么基金"
这种 FOF 场景的灵魂问题。

## v0.1 边界

我尽量诚实：

✅ 跑通的：
- agent loop + 流式 SSE
- 2 LLM provider + 6+ 实测 LLM 兼容
- 5 个 Tushare 工具 + 自定义 plugin 协议
- 多会话 SQLite + 审计日志
- Docker compose 一行起 + GitHub Actions CI

❌ v0.1 还没做的：
- 多用户登录（架构里 `user_id` 字段位已留好；v0.2 加 OIDC）
- entry_points 自动插件发现（v0.2）
- 工具结果缓存（v0.3）
- Markdown / PDF 研报导出（v0.4）

❌ 数据层固有局限：
- A 股历史行情 Tushare 端默认未复权，长跨度回报对比会失真
- 没有一致预期数据（Tushare 没开源；要接朝阳永续是商用接口）
- A 股年报 PDF 没有 SEC Item 那种结构化切片，能给你公告 URL 但不能切章节

## 为什么开源 + MIT

技术选型一开始就是为了能开源、能被 fork、能被商用：

- **MIT** 而非 AGPL：方便后续做托管版、企业版而不卡 license
- **核心 vs 插件分离**：`tushare_tools()` 是个工厂函数返回 ToolSpec
  列表，没有任何 `from app.fof import ...`；你想替换数据源、加港股、
  加加密货币，只要照模板写就行
- **provider 用最小子集 OpenAI-compat**：避免锁定，也避免 langchain
  那种几百兆依赖

Roadmap 里有「托管版」「企业版」的位置——但**核心永远 MIT**。
